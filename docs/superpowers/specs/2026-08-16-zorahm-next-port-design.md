# Порт zorahm.ru на Next.js + WebGL

Дата: 2026-08-16

## Задача

Переписать одностраничный сайт-визитку `zorahm-halftone.html` (550 строк, один файл)
на Next.js. Визуал и содержание переносятся один в один, попутно чинятся слабые места.

## Исходник

Скролл-страница из 8 «кадров». Каждый кадр — фигура, собранная из halftone-сетки
точек (~13 000). Фигура рисуется на офф-скрин канвас размером `cols×rows`, затем
яркость пикселей превращается в размер точек.

Кадры: Сатурн → шум данных → нейросеть → глаз → глобус → круги влияния → GitHub → знак `Z\M`.

### Что именно тормозит

Не HTML. Два места:

1. `getImageData()` каждый кадр, на переходах — дважды. Синхронное чтение
   пикселей GPU→CPU, стопорит пайплайн. Главный тормоз.
2. ~13 000 `ctx.arc()` в один path на кадр, на CPU.

## Решения

| Вопрос | Решение |
|---|---|
| Фреймворк | Next.js 16.3.1, App Router, TypeScript, статический экспорт |
| Стили | CSS Modules + те же CSS-переменные. Tailwind отклонён |
| Поле точек | WebGL через React Three Fiber |
| DOM-анимация | `motion` (ex-framer-motion) |
| Состояние скролла | `zustand` с transient-подпиской |
| Шрифты | `next/font`: Unbounded (заголовки) + IBM Plex Mono (текст) |

Tailwind отклонён потому, что дизайн стоит на `clamp()`, многослойных
`radial-gradient` и `mask-image` — в Tailwind это выродится в сплошные
arbitrary-значения.

### Главное структурное изменение

В исходнике кадр разорван надвое: текст в `<section data-stage="3">`, фигура
в `SHAPES[3]`, связь — порядковый номер. Рассыплется от перестановки секций.

Теперь кадр собирается из двух половин, каждая со своей причиной меняться:

- `structure.ts` — порядок, выравнивание, `accent`, наличие CTA и контактов.
  Одинаково для всех языков.
- `en.ts` / `ru.ts` — только тексты: `label`, `eyebrow`, `title`, `body`.

`getFrames(lang)` их склеивает. Правка перевода физически не может разъехаться
с вёрсткой, а перестановка секций — с фигурами. Поле языка не знает вовсе:
`Halftone` берёт `FRAME_STRUCTURE`.

Добавить кадр = одна запись в структуре, по записи в каждый словарь и один
файл в `shapes/`. Тест проверяет, что словари покрывают все кадры и совпадают
по составу абзацев.

## Двуязычность

Английский — основной, лежит в корне; русский — на `/ru`.

`output: 'export'` исключает middleware, поэтому язык задаётся маршрутом, а не
переговорами с сервером. `<html lang>` умеет ставить только root layout, а он
в App Router один на дерево — поэтому используются route groups `(en)` и `(ru)`
с двумя корневыми макетами. Общая обвязка (шрифты, метаданные, viewport)
вынесена в `app/shared.tsx`.

Метаданные локализованы: `title`, `description`, `og:locale`, `canonical`.
`hreflang` перечисляет обе версии плюс `x-default` на английскую.

Переключатель языка стоит в HUD справа сверху, симметрично метке `Z\M`.

## Движок поля

### Проход 1: фигуры → render target

Каждая активная фигура пишет поле яркости в FBO размером `cols×rows` (~100×60,
около 6000 пикселей). Активных фигур максимум две: текущая и следующая.

FBO обязателен, а не факультативен: поле нужно только в узлах сетки (6000
значений), экран — 2 000 000 пикселей. Считать SDF на каждом пикселе экрана
вместо каждого узла — в 340 раз лишней работы.

### Проход 2: InstancedMesh

`cols×rows` инстансов. Вершинный шейдер читает оба поля через `texelFetch`,
миксует по прогрессу, считает позицию (отталкивание от курсора + волновой дрейф)
и размер. Фрагментный рисует круг.

**Ось Y не инвертируется.** Узел с `aNode.y = 0` лежит внизу и в поле (в render
target `gl_FragCoord` растёт вверх), и на экране. Попытка перевернуть Y в
`gl_Position` даёт две беды сразу: картинка отражается по вертикали, а порядок
обхода вершин выворачивается — квады становятся обратной стороной к камере и
целиком съедаются backface culling'ом, который three включает по умолчанию.
У материала стоит `side: DoubleSide`: точки плоские, отбраковывать нечего.

Курсор приходит в экранных координатах (Y вниз) и переворачивается один раз,
в `useFrame`, — и для поля, и для точек.

**Почему инстансинг, а не полноэкранный шейдер.** В полноэкранном варианте
смещение точек от курсора приходится обращать: для пикселя искать, какой узел
на него наехал. Смещение до 34px при шаге сетки 12–15px — узел уезжает на 2.3
ячейки, значит перебор соседей 5×5 = 50M выборок из текстуры на кадр. При
инстансинге смещение применяется напрямую, как сейчас в JS. 13 000 инстансов —
один draw call.

Два бонуса: золотые точки перестают требовать второго прохода (цвет выбирается
во вершинном шейдере), отсечка `v < .035` становится схлопыванием вершины в ноль.

### Типы фигур

**Процедурные (5)** — фрагментный шейдер пишет яркость прямо в FBO:

- `noise`, `ripple` — уже чистая математика в `calc()`, переносятся построчно
- `network` — 21 узел, 98 связей, SDF отрезка
- `globe` — эллипсы, SDF
- `eye` — vesica piscis (пересечение двух окружностей) вместо кривых Безье;
  получается проще исходника

**Запечённые (3)** — Canvas2D рисует один раз при resize, результат в текстуру:
`saturn`, `github` (контур `Path2D`), `mark` (глиф шрифтом).

Динамика добавляется процедурно поверх сэмпла: обломки и коммиты на орбитах
считаются в шейдере, пульсация масштаба — сэмпл по масштабированному UV, бегущая
волна по знаку — умножение на градиент.

### Известные потери

Наклон колец Сатурна колеблется на `sin(t*.12)*.03` = 1.7°. В запечённом
варианте поворачивается UV целиком; планета круглая и поворот её не меняет, но
пояса повернутся вместе с кольцами. На 1.7° неразличимо.

Вертикальный дрейф поясов (2% радиуса) запекается в среднем положении.

Это единственные потери. Если на прототипе окажутся заметными — фигура
доперeводится в процедурную, интерфейс у обоих типов один.

### Что переносится без изменений

Механика `settle` (фигура «дособирается», потом оживает). Формулы едут
в `useScrollStage.ts` чистыми функциями от прогресса скролла: ни DOM, ни canvas,
ни времени внутри — покрываются юнит-тестами напрямую.

## Состояние скролла

`stagePos` обновляется каждый кадр, поэтому `useState` исключён — это 60
перерендеров в секунду. Используется `zustand`:

- R3F читает `useStore.getState()` в `useFrame` без подписки
- HUD подписывается на производные целые значения (номер кадра, процент)

## Чистка

- Пустые `href="#"` в контактах → реальные ссылки
- `100vh` → `100dvh`: на мобильных адресная строка ломает `100vh`
- Метаданные: title, description, lang, Open Graph, theme-color
- Доступность: `prefers-reduced-motion`, фокус-стили, поле скрыто от
  скринридеров, блок контактов размечен как `nav`

### Исправленные дефекты исходника

Найдены по ходу порта, все три — в перенесённой логике:

1. **Демпфирование зависело от частоты кадров.** `pos += (target - pos) * 0.12`
   означало 12% за кадр: на 120 Гц доводка шла вдвое резче, чем на 60 Гц.
   Теперь коэффициент считается по реальному `dt`, ощущение на 60 Гц прежнее.
2. **Последний кадр терял `settle`.** `blend` вычислялся до проверки, есть ли
   куда переходить, поэтому на восьмом кадре — где сменять нечем — фигура
   всё равно «разбиралась»: доскроллив страницу до конца, знак `Z\M`
   переставал жить. Теперь `blend` обнуляется до того, как попадёт в `settle`.
3. **Глаз косил, когда мыши нет.** При отсутствии курсора подставлялось
   `-9999`, после `clamp` дававшее `-1` — то есть максимальный поворот
   влево-вверх вместо взгляда прямо.

### Отдельно: пересоздание запечённых текстур

`CanvasTexture` берёт размер холста в момент первой загрузки. При изменении
размеров окна холст перерисовывается крупнее, и `needsUpdate` пытается залить
больший кадр в прежнее хранилище — GL отвечает `GL_INVALID_VALUE`. Поэтому при
смене размеров вызывается `dispose()`, и хранилище создаётся заново.

## Тестирование

- Vitest на чистые функции: механика кадров (`stage.ts`) и геометрия сетки
  (`grid.ts`) — 27 тестов
- Production-сборка и ESLint
- Проверка в браузере: все восемь кадров сняты с canvas через `readPixels` и
  сверены по форме

Замечание о проверке: встроенный браузер **не захватывает WebGL-слой в
скриншотах** — страница на них выглядит пустой, хотя поле отрисовано. Судить
о рендере по скриншоту здесь нельзя, нужен `readPixels` (он требует
`preserveDrawingBuffer: true`, который включается только на время замера).

## Файлы для краулеров

| Файл | Источник | Что внутри |
|---|---|---|
| `/robots.txt` | `app/robots.ts` | Обход разрешён всем, ИИ-агенты перечислены поимённо |
| `/sitemap.xml` | `app/sitemap.ts` | Обе языковые версии со связкой через `xhtml:link hreflang` |
| `/llms.txt` | `app/llms.txt/route.ts` | Описание сайта, ссылки, контакты и полный текст обеих версий |

Все три собираются из `SITE_URL` и словарей контента, а не из литералов —
домен и тексты задаются в одном месте.

**ИИ-краулеры разрешены осознанно.** Формально их покрывает правило `*`, но
поскольку многие сайты их блокируют, агенты (GPTBot, ClaudeBot, PerplexityBot,
Google-Extended и другие) перечислены отдельным правилом — так разрешение
читается как решение, а не как недосмотр.

**Почему `llms.txt` содержит полный текст.** Страница рисует содержимое в WebGL
и раскрывает его по скроллу — краулеру пришлось бы исполнять её целиком. Здесь
весь текст обеих версий лежит готовым. Файл генерируется из тех же словарей,
что и страница, поэтому не может устареть после правки текстов; тесты проверяют,
что каждый заголовок и абзац в него попали.

**Грабля статического экспорта.** Каждый из трёх маршрутов требует явного
`export const dynamic = "force-static"` — иначе сборка падает с ошибкой про
`output: export`. Для `sitemap.ts` причина в `new Date()`, но Next требует
пометку и там, где динамики нет вовсе.

## Иконки

Логотип — знак `Z\M`: белые Z и M, слэш золотой, как в HUD. Нарисован
геометрическими путями (без текста), поэтому не зависит от шрифта и остаётся
чётким на любом размере.

- `public/icon.svg` — 64×64, тёмная подложка со скруглением
- `public/apple-icon.png` — 180×180 для iOS, без скругления (его накладывает
  сама система)

Обе иконки объявлены в метаданных явно. Два повода не полагаться на
автоподхват файлов из `app/`:

1. **Любой ручной ключ в `icons` отменяет автоматически найденные иконки.**
   Стоило добавить один только `apple`, как тег SVG-иконки пропал из HTML.
2. **Сгенерированный маршрут отдаёт PNG по пути без расширения**
   (`/apple-icon`), из-за чего обычный статический хостинг подставит неверный
   MIME-тип и iOS иконку не подхватит.

## Домены

Всё живёт на `zorahm.com`; `.ru` не продлевается. Домен задан один раз —
`SITE_URL` в `content/types.ts`, — и оттуда расходится по canonical, hreflang,
Open Graph и футеру. Почта: `me@zorahm.com`.

## Открытые вопросы

1. **Английские тексты — машинный перевод, нужна вычитка.** Русские тексты
   авторские и художественные («Сначала шум», «Она смотрит в ответ»); английская
   версия переведена мной с попыткой сохранить ритм, но это не авторский голос.
   Править в `content/en.ts`.
2. **Telegram.** Стоит `t.me/zorahm` — проверить, что аккаунт тот.
## Шрифт заголовков

Исходный Bricolage Grotesque кириллицу не покрывает (latin, latin-ext,
vietnamese), из-за чего русские заголовки молча уезжали на Arial Black. С
появлением английской версии это стало заметным расхождением между языками,
поэтому заголовки переведены на **Unbounded** — variable-гротеск с родной
кириллицей и латиницей, оси 200–900.

Проверено: шрифт применяется на обоих алфавитах (он на 22% шире Arial по
метрикам), заголовки не выходят за границы ни на 1697px, ни на 375px,
горизонтального скролла не возникает.

### Побочно найденный дефект

В запекании глифа `Z\M` шрифт задавался литералом `"Bricolage Grotesque"`, а
`next/font` подставляет сгенерированное имя вида `__Unbounded_a1b2c3`. Canvas2D
молча брал фолбэк, то есть знак всё это время запекался не тем шрифтом. Теперь
семейство читается из CSS-переменной `--font-display`.
